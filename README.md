## Prerequisites

- node<sub><sup>`>=24.0.0`</sup></sub>
- npm<sub><sup>`>=11.0.0`</sup></sub>

## Install

1. Run `npm install`.

## Running the application

1. Run `npm run dev` to start the client.
2. Check it out under: `http://localhost:5173/`.

### The Application

- On the initial load the user sees the app that displays a list of football rating player cards.
- Each card has a photo, name, overall rating, position, age, height and current football club that the player represents.
- Users can view in-depth information about each player by clicking on the card.
- For loaded players, user can perform local search.

### General Approach

- The architecture is loosely based on _feature sliced design (FSD)_.
- The app bundler is `vite`.
- The application is written in `Typescript`.
- Component are built with teh `Material UI`
- Fetching, caching and virtualisation are all done with `tanstack` libraries.
- Design generated by `Google Stich` and can be found in [here: Figma link](https://www.figma.com/design/oIWfJhWCOK1usv3TwE96lz/).

### Architecture explanation

- The domain of the application is to visually represent a list of player cards.
- FSD helps are to represent this feature as multiple layers, that are then stacked together in specific order: `entities` -> `features` -> `widgets` -> `pages`.
- This strict import order mandate guarantees one directional flow of the interfaces, providing the project with clear organisation and scalability patterns.
- Strict `eslint` superset of rules (_eslint-unicorn_) and `husky` + `lint-staged` perform as a code quality guard.

### Technical decisions

- For cross-platform safety and to prevent issues with case-sensitivity in different environments, _kebab-case_ is used in naming files.
- `Vite` is used as a bundler, offering great out-of-the box functionality.
- `Prettier` controls the layout of the code.
- `.nvmrc` and `.npmrc` guarantees strickt dependency versions, assuring that app will be configured in the same way in any enviorment.

### Application core functionality

- App has simple pagination functionality represented in infinite scroll, where a user loads more users the moment he viewed the last card in the list. This functionality is achieved with `@tanstack/react-query`.
- Virtualisation feature (`@tanstack/react-virtual`) guarantees that at no time of scrolling through the list of cards browser renders more items than it shows on the screen.
- Cache and offline are handled by `@tanstack/react-query`.

### Trade-offs

- Potential inconsitancies in usage of `MUI` can lead to some rough edges due to lack time restrain.
- Testing coverage is insufficient due to the nature of the project and time restrain.

### What you would improve with more time

- There is no perfect way to test core functionality like pagination without either relying heavily on the mocks at the unit level or building browser interceptions at the integration level because CORS (the EA API does not support browser CORS) would not allow an application to make an endpoint call to the _EA_ server. Given more time, testing strategy and coverage can be significantly improved.
